# Check2GO Recovery Map

Recovered read-only from the Check2GO AWS account on 2026-09-13.

## 1. What is recoverable from AWS

### Amplify Gen 1 backend — HIGH confidence
- App: `check2go`
- Environment: `dev`
- Region: `eu-north-1`
- Root CloudFormation stack: `amplify-check2go-dev-6e50a`
- Historical backend archive still exists in S3: `#current-cloud-backend.zip`
- The deployment bucket contains 248 objects, including original Amplify backend source/config, generated GraphQL schema, resolvers, model introspection and CloudFormation artifacts.

### Data/API schema — HIGH confidence
Original source schema recovered with these domain models:
- `TravelAmplify`
- `TravelerAmplify`
- `TaskTemplateAmplify`
- `TaskAmplify`
- generated many-to-many join model `TravelerTravelAmplify`

Relationships:
- Travel ↔ Traveler: many-to-many
- Travel → Task: one-to-many
- Task → Travel: belongs-to
- Task templates support parent-child hierarchy using `parentId`

### Authentication — HIGH confidence
- Amazon Cognito User Pool + Identity Pool
- Email verification
- Email / phone username configuration
- MFA configured OFF
- Unauthenticated identities disabled
- Model access uses owner authorization through Cognito

### AppSync — HIGH confidence
- GraphQL API: `check2go-dev`
- DynamoDB data sources
- CRUD queries/mutations and subscriptions generated by Amplify
- Historical default API auth used an API key with Cognito User Pools as an additional provider

### DynamoDB — HIGH confidence
Five Check2GO application tables remain. Observed item counts were 0 at inspection time, so this environment appears to contain schema/infrastructure rather than production user data.

## 2. 2026 sandbox is a different backend
A second Amplify environment was created on 2026-01-31 under `amplify-check2go-max-sandbox-...`.
Its model schema contains only `Todo` and is not equivalent to the 2025 Check2GO backend.

## 3. Important recovery observations
- AWS preserves enough backend material to rebuild the core GraphQL/Cognito/DynamoDB infrastructure.
- The original Flutter application source (`lib/`, `pubspec.yaml`, `android/`, `ios/`) was not found in AWS Amplify/CodeCommit during the scan.
- Likely recovery path: frontend from APK(s) + backend from AWS + UX from Figma + current product requirements.
- The historical schema contains a global public authorization line explicitly marked `FOR TESTING ONLY!`; do not blindly reproduce it in production.
- The field name `familyAffination` is preserved exactly because that is how it exists in the historical schema. Renaming it requires a deliberate migration.
