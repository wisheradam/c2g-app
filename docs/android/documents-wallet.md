# Android Documents wallet

The Documents bottom-navigation destination is a device-only travel document wallet.

## Architecture

- `DocumentCatalog.kt` is the configuration source for categories, predefined types, and dynamic fields.
- `TravelDocument.kt` defines independent document records, attachments, status calculation, search, sorting, and extension points for later OCR, ownership, trips, verification, notifications, and country metadata.
- `LocalDocumentStore.kt` persists metadata and files locally. Metadata and every attachment are encrypted with AES-GCM keys generated by Android Keystore.
- `DocumentsScreen.kt` provides global search, sorting, category accordions, compact rows, and edit/delete actions.
- `DocumentEditorScreen.kt` provides the category/type flow, configuration-driven fields, custom types, consent, and attachment management.

## Storage and privacy

There is no network or backend integration. Metadata is stored in private app preferences as ciphertext. Imported PDF/JPEG/PNG files are copied into private app storage and encrypted; external source URIs are not retained. Files are decrypted only into app cache when the user explicitly opens them through Android's `FileProvider`.

Android cloud backup and device-transfer backup are disabled for the application. Uninstalling the application or clearing its app data deletes the wallet and its non-exportable encryption keys.

## Backend

The historical GraphQL schema is unchanged. No migration or environment variables are required.

## Future extensions

The model reserves stable fields for owner/family member, trip, source, verification state, extracted data, notification settings, country metadata, and record version. OCR, AI classification, sharing, notifications, server synchronization, and version-history UI are intentionally not implemented in this phase.
